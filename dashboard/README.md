# لوحة تحكم الرابطة — دليل الاستخدام

## طريقة الدمج
انسخ مجلد `admin/` إلى جذر مشروعك الحالي، بجانب `index.html` و
`favicon.png` مباشرة. لا حاجة لأي تعديل على ملفات موقعك الحالية.

```
مشروعك/ (= htdocs على InfinityFree)
├── index.html, news.html, ... (ملفات الموقع العام الحالية)
├── favicon.png
├── analytics-tracker.js   ← تتبع الزوار للموقع العام
└── admin/                 ← لوحة التحكم بالكامل
    ├── login.html          صفحة الدخول (تسجيل دخول حقيقي)
    ├── index.html          الرئيسية: إحصائيات + رسوم + حالة الخدمات
    ├── content.html        الأخبار / الإنجازات / الأنشطة
    ├── suggestions.html    المقترحات والبلاغات
    ├── ads.html            الإعلانات
    ├── analytics.html      تحليلات تفصيلية
    ├── users.html          المستخدمون + سجل العمليات
    ├── backup.html         نسخ احتياطي (تنزيل JSON حقيقي)
    ├── settings.html       إعدادات الموقع
    ├── config.js           نقطة الإعداد المركزية الوحيدة
    ├── css/admin.css       نظام تصميم SaaS مستقل
    └── js/
        ├── api-adapter.js         كل البيانات تمر من هنا
        ├── auth.js                حارس الجلسة (طرف المتصفح) + قراءة/حفظ التوكن
        ├── auth-check-redirect.js تجاوز صفحة الدخول إن كانت الجلسة صالحة
        ├── layout.js               الشريط الجانبي/العلوي + التنقل حسب الدور
        ├── modal.js                نافذة منبثقة عامة (نماذج/تأكيدات)
        └── utils.js                تنسيق تاريخ/أرقام + تنقية HTML
```

## الحالة الحالية: مربوطة فعلياً بالخادم ✅
هذه ليست نسخة تجريبية (mock) — تسجيل الدخول وكل وحدات المحتوى/
الإعلانات/المقترحات/التحليلات/المستخدمين متصلة فعلياً بأربعة
مشاريع Google Apps Script منفصلة (`Airtable.js`،
`Suggestions-AppsScript.js`، `Analytics-AppsScript.js`،
`Users-Auth-AppsScript.js` — هذه الأربعة ليست جزءاً من هذا الزيب،
تُنشر بشكل منفصل من Google Apps Script، لا تُرفع على الاستضافة).

**المصادقة**: تسجيل دخول واحد من `login.html` يصدر رمز جلسة موقَّع
(HMAC-SHA256) صالح لساعتين. `js/api-adapter.js` يرسل هذا الرمز مع
كل طلب إداري، وكل مشروع Apps Script الأربعة يتحقق من توقيعه ودور
صاحبه محلياً قبل تنفيذ أي عملية حساسة. لا توجد أي كلمة سر مشتركة
داخل `config.js` أو أي ملف frontend.

**الأدوار الثلاثة** (تُفرض من الخادم، وليس فقط بإخفاء الأزرار):
مدير عام (كل الصلاحيات) / محرر محتوى (المحتوى فقط) / مشاهد فقط
(قراءة فقط).

النسخ الاحتياطي (تنزيل JSON) وإعدادات الموقع لا تزالان تعملان محلياً
فقط (بلا حفظ دائم في Drive/Sheet) — هذه أولوية 2 القادمة، وليست جزءاً
من هذا التسليم.

## ✅ جديد — ألوان الهوية
راجع `/CLAUDE_CONTEXT.md` في جذر المشروع للتفاصيل الكاملة والخطوات
اليدوية المتبقية (تشغيل createSuperAdminAccount). باختصار: لون الموقع
ولون اللوحة أصبحا قابلين للتغيير من "إعدادات الموقع" في اللوحة
(`js/theme.js` الجديد).
⚠️ تسجيل الدخول بحساب قوقل أُزيل بالكامل من اللوحة (كان يمنح أي حساب
قوقل جديد دور "محرر محتوى" تلقائياً بلا مراجعة بشرية). الدخول الآن
باسم المستخدم/كلمة السر أو "الدخول كزائر" فقط.

## رفعها على InfinityFree
1. سجّل دخول إلى لوحة تحكم الاستضافة → File Manager (`filemanager.ai`).
2. ادخل إلى مجلد `htdocs` **تحديداً** (وليس جذر الحساب).
3. ارفع محتوى هذا الزيب بحيث يصبح مجلد `admin/` مباشرة داخل `htdocs`،
   بجانب ملفات الموقع العام الحالية (لا تستبدل أي ملف من الموقع
   العام — هذا الزيب يحتوي فقط على `admin/`).
4. تأكد أن الروابط الأربعة داخل `admin/config.js` هي أحدث روابط
   Deploy → Web App من Google Apps Script (تُنسخ من "New deployment"
   أو "Manage deployments" بعد أي إعادة نشر).
5. افتح `https://<دومينك>/admin/login.html` وجرّب الدخول بحساب حقيقي
   من جدول Users في Airtable.

## نقطة مهمة عند إعادة النشر لاحقاً
كل ما يتغيّر عند تحديث الروابط أو إعادة استخدام اللوحة لمشروع آخر هو
`admin/config.js` و`admin/js/api-adapter.js` فقط — بلا لمس أي صفحة
HTML أخرى في اللوحة.


## Dashboard V2 — المرحلة الأولى

- إعادة تنظيم التنقل حول الأكاديمية والمحتوى والتشغيل.
- إزالة الإعلانات التجارية من قائمة اللوحة.
- اعتماد دور `مسؤول أكاديمي` وإلغاء `مشاهد فقط` كدور إداري معتمد.
- إضافة إدارة الجداول الدراسية من داخل اللوحة: عرض، إضافة، تعديل، حذف، تفعيل/تعطيل.
- منع التعارضات الزمنية على الخادم.
- الجداول مخزنة في Google Sheet داخليًا، لكن المسؤول لا يحتاج إلى فتحه.
- المواد الدراسية في هذه المرحلة للاستعراض فقط؛ رفع/حذف ملفات Drive يحتاج طبقة نقل ملفات مخصصة، ولن نضع أزرارًا وهمية.

### Backend

استخدم `Unified_API_v1.3.gs` مع `Users.js` المحدّث. بعد النشر يصبح `scheduleAdminList / scheduleCreate / scheduleUpdate / scheduleDelete / scheduleToggle` محميًا بجلسة المسؤول.


## الاستضافة النهائية للوحة

النسخة الحالية مجهزة للنشر على **Cloudflare Workers** باستخدام Static Assets بدل GitHub Pages.

- Worker name: `leo-association-dashboard`
- ملف إعداد Wrangler: `dashboard/wrangler.toml`
- النشر الآلي: `.github/workflows/deploy-dashboard.yml`
- أسرار GitHub المطلوبة: `CLOUDFLARE_API_TOKEN` و `CLOUDFLARE_ACCOUNT_ID`

### حماية الإنتاج

بعد اختيار الدومين النهائي، اربط اللوحة على نطاق مثل `admin.<domain>` ثم أنشئ Cloudflare Access application على نفس الـhostname. Access تكون طبقة حماية إضافية قبل وصول المستخدم إلى اللوحة، بينما يبقى Staff Authentication داخل التطبيق مسؤولًا عن الأدوار والصلاحيات.

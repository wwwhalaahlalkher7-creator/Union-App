# TRINEX — المرحلة 1: إصلاح وتحسين CRUD الإدارة

## الهدف

إصلاح أخطاء CRUD المكتشفة في مراجعة Release Candidate، وتوحيد دورة حياة المحتوى بين API وDashboard، وإضافة اختبارات تمنع عودة الأخطاء نفسها.

## ما تم إصلاحه

### 1. حذف المحتوى

الجداول:

- `news`
- `activities`
- `announcements`
- `achievements`

لا تستخدم عمود `active`. أصبح DELETE في لوحة الإدارة يعني **أرشفة** السجل عبر:

```sql
status = 'archived'
```

وتظل السجلات محفوظة في D1 مع سجل التدقيق، بينما الـpublic API يعرض `published` فقط.

### 2. السجلات التشغيلية

الجداول:

- `materials`
- `schedules`
- `students`
- `subjects`
- `badges`

تستمر في استخدام:

```sql
active = 0
```

عند DELETE الإداري.

### 3. إصلاح أعمدة CRUD — تثبيت إصلاحين Regression

تم تصحيح إسقاطات الإدارة لتطابق مخطط D1 الفعلي، ومنها:

- **`announcements`:** إزالة `updated_by` من حقول CRUD والإسقاط والتحديث؛ المخطط الحالي لا يحتوي هذا العمود.
- **`schedules`:** إزالة `created_at` من إسقاط الإدارة وأي اعتماد عليه؛ المخطط الحالي يحتوي `updated_at` فقط.
- إضافة اختبارات Regression صريحة تمنع إعادة إدخال هذين العمودين في CRUD مستقبلًا.
- إضافة الحقول الجديدة للمحتوى إلى `ADMIN_FIELDS` و`ADMIN_SELECT_COLUMNS`.

### 4. تحديث المحتوى

تم منع فقدان بيانات المحتوى الجديدة أثناء التعديل، بما في ذلك:

- تصنيف وناشر الأخبار.
- موقع وناشر ووقت نهاية الأنشطة.
- المقدمة والمحاور والتصنيف والناشر والصور للإنجازات.

كما أصبح تحديث السجل يحافظ على حالته الحالية (`draft` / `published` / `archived`) بدل إعادة نشر السجل المؤرشف دون قصد.

### 5. Dashboard

تم تحديث واجهة المحتوى بحيث تعرض:

- منشور
- مجدول
- مسودة
- مؤرشف

وأصبح زر الحذف يعكس السلوك الحقيقي: **أرشفة** بدل الإيحاء بحذف نهائي.

## الاختبارات

تمت إضافة:

```text
ci/admin_crud_check.py
```

ويتحقق من:

1. تطابق `ADMIN_FIELDS` مع D1 schema.
2. تطابق `ADMIN_SELECT_COLUMNS` مع D1 schema.
3. صحة SQL لتحديث المحتوى.
4. صحة أرشفة أنواع المحتوى الأربعة.
5. صحة soft-delete للجداول التشغيلية.

كما تم ربط الاختبار بـ Backend CI.
